# 墨排 AI 编辑器设计说明

## 目标

在不修改现有项目任何文件的前提下，新建一个完全独立的公众号文章生成工具。用户只输入一句话创作需求，系统通过用户提供的 OpenAI 兼容接口生成完整 Markdown 文章和结构化排版决策，再严格读取 `isjiamu/gzh-design-skill` 的所选主题原组件库装配可复制到微信公众号的 HTML。

## 成功标准

- 新项目位于 `H:\项目合集\skill\mopai-ai-editor`，拥有独立的源码、依赖和构建产物。
- 用户可填写任意 OpenAI 兼容接口的 Base URL、API Key 和模型名。
- 用户可输入一句话创作需求，并生成完整文章与排版成品。
- 写作阶段返回完整 Markdown 正文和结构化决策；排版阶段按原仓库主题组件生成 HTML。
- 用户可查看 AI 判断理由，并手动覆盖主题、文章类型和排版开关。
- 可实时预览 375px 公众号 HTML，可复制富文本并导出 HTML。
- 调用失败不会清空需求或上一次有效文章，并显示可理解的错误类型。
- API Key 不写入 localStorage、日志或项目文件。
- 桌面端与移动端核心工作流均可使用。

## 范围

### 包含

- React、TypeScript、Vite 前端。
- 本地 Node.js 接口代理。
- OpenAI 兼容的 Chat Completions 请求。
- Markdown 解析和确定性公众号 HTML 生成。
- 六套主题、七类文章配方和有限的智能排版开关。
- 本地草稿保存、复制富文本、导出 HTML、错误恢复。

### 不包含

- 用户账户、云端同步、计费和团队协作。
- 图片生成、素材库和自动发布公众号。
- 任意 Skill 的通用编排平台。
- Electron 桌面打包。
- 联网查资料、引用核验和图片生成。

## 架构

项目采用单仓库双进程结构：

- `src/`：React 前端，负责一句话输入、生成结果编辑、状态展示、预览和导出。
- `server/`：本地 Node 服务，负责校验请求、调用 OpenAI 兼容接口、提取结构化结果和归一化错误。
- `vendor/gzh-design-skill/`：原仓库 SKILL、六套主题、公共组件、校验脚本和许可证的原样副本。

开发时由 Vite 运行前端，本地 Node 服务提供 `/api/generate-layout`。生产构建后，Node 服务同时托管静态前端文件。接口地址、密钥和模型名随单次请求从前端传给本地服务；服务不持久化这些信息。

## 核心数据流

1. 用户输入一句话创作需求。
2. 前端检查必填项，并向本地服务发送接口配置和创作需求。
3. 本地服务调用用户指定的 OpenAI 兼容 Chat Completions 接口。
4. 模型按固定 JSON 结构返回完整 Markdown 文章和排版决策。
5. 服务根据主题读取原始 `theme-*.md`、`common-components.md` 和 `SKILL.md`，发起第二阶段装配。
6. 服务使用原仓库校验脚本验证 HTML，通过后返回文章、决策和成品。
7. 用户可以手动覆盖任何可见决策，预览同步更新。
8. 用户复制富文本或导出纯正文 HTML。

## 排版决策结构

模型返回以下有限字段：

- `articleType`：教程、清单、观点、访谈、数据、随笔或案例。
- `themeId`：六套内置主题之一。
- `reasoning`：不超过三条、面向用户的简短判断理由。
- `autoNumber`：是否为章节自动编号。
- `keywordUnderline`：是否标记关键内容。
- `includeToc`：是否生成精选目录。
- `componentPlan`：从当前主题允许的组件集合中选择核心组件和点缀组件。

服务端拒绝未知字段和非法枚举。校验失败时不会应用部分结果。

## 界面设计

沿用现有项目实际截图的轻量、高密度三栏编辑工作台，不复制或修改原项目代码。

### 顶部栏

- 左侧：墨排品牌。
- 中间：文章标题和自动保存状态。
- 右侧：接口设置、生成文章、导出 HTML、复制到公众号。

### 左栏

- 顶部为一句话创作需求和生成按钮。
- 下方为生成后的 Markdown 文章编辑器。
- 底部显示章节数、行数和字数。

### 中栏

- 显示 375px 宽的真实公众号 HTML。
- 保持独立滚动和 70% 至 110% 缩放。
- 生成期间保留上一次结果，并显示非遮挡式进度状态。

### 右栏

- AI 判断理由和最近一次生成状态。
- 主题组件库。
- 文章类型与组件配方。
- 智能排版开关。
- 已识别内容统计和公众号兼容性检查。
- AI 生成的选择可由用户手动覆盖。
- 修改文章或主题后，通过“重新应用原组件”再次按对应主题装配。

### 接口设置

使用模态窗口填写 Base URL、API Key 和模型名。Base URL 与模型名可选择保存到本地；API Key 仅保存在当前页面内存中，刷新后需重新填写。界面提供连接字段校验，不单独发送探测请求。

### 响应式布局

桌面端保持三栏。宽度小于 860px 时使用“创作 / 成品 / AI 决策”三个切换页，顶部保留主要生成和复制动作。

## 错误处理

- 地址错误：提示检查 Base URL。
- 401 或 403：提示密钥或接口权限错误。
- 404：提示接口路径或模型不存在。
- 429：提示额度或频率限制。
- 超时或断网：允许原参数重试。
- 非 JSON 或结构不合法：提示模型未按格式返回，保留上一次结果。
- 本地服务未启动：提示启动完整开发命令，而不是显示通用网络错误。

错误信息不回显 API Key，不记录完整请求头。

## 本地持久化

localStorage 只保存：

- 生成后的 Markdown 文章。
- 一句话创作需求。
- Base URL 和模型名。
- 最近一次有效排版决策。
- 用户手动覆盖后的排版设置。

API Key 不保存。保存失败时应用仍可继续使用，只是不提供刷新恢复。

## 测试与验收

- 单元测试：决策 Schema、Markdown 解析、主题约束、HTML 合规检查和错误归一化。
- 接口测试：成功响应、401、429、超时、非法 JSON 和非法枚举。
- 交互测试：填写配置、一句话生成文章、手动编辑、排版覆盖、复制、导出和刷新恢复。
- 视觉验证：桌面三栏、375px 预览、860px 以下移动切换、无横向溢出。
- 安全检查：源码、localStorage、构建产物和日志中均不存在测试 API Key。
- 构建验证：类型检查、测试和生产构建全部通过。
